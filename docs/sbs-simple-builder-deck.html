The claim · what the machine is for

02 / 18

A strategist writes one paragraph. A client sees three finished pages.

Everything between those two facts is this application. It reads the brief, decides which of 156 registered DST patterns the page should be built from, writes the copy for every band, finds and places the imagery, and renders the result as a live page you can edit — then exports it as block JSON a WordPress plugin turns into real, editable Gutenberg blocks.

It runs entirely in the browser. The only server is a thin proxy in front of a language model and a stock-image API: no database, no build step per project, no session state. A project is one JSON object in localStorage.

The design constraint that shapes everything

The preview is not a mock-up of the output. It is rendered from the same node tree the export serialises. When they disagree, that is a bug with a name — and there is a test for it.

Two front doors, one engine

The simple builder is four steps and plain language. The advanced builder is five steps over the same project, exposing every registered DST attribute. Switching between them loses nothing, because there is only one project.

Step 01 · Brief and Direction

05 / 18

The brief arrives as a paragraph, a PDF, or both.

Typed

A textarea, capped at 16,000 characters. The counter and the button's gate both measure the whole brief.

Attached

Drop a PDF, .docx, .rtf or any text file anywhere on the window. It is read in the browser — nothing is uploaded — and shows as a named attachment, not as pasted text.

briefSourceText()

One function decides what "the brief" is: the paragraph, then each document announced by its own file name. Every consumer reads it, so they cannot disagree.

The PDF reader is written from scratch and has no dependency: DecompressionStream for the Flate streams, a table walk for /ObjStm object streams, and a /ToUnicode CMap resolver for Identity-H CID fonts — which is what Word and Chrome actually export. A PDF stores no spaces and no lines, so word gaps are inferred from kerning and line breaks from pen position.

→

What the reader handles

WinAnsi TrueType and Identity-H CIDFontType2 in the same file; PDF 1.5+ compressed object streams; DOCX as a ZIP with a deflated word/document.xml; RTF control-word groups; HTML.

→

What it refuses, by name

A scan. If less than 55% of the extracted characters are letters, it says so and asks for the text instead of handing the model noise.

Step 01 · what a concept actually is

07 / 18

Three workspaces, one brief.

Each concept holds its own design, sections, header, footer and flow. The brief, the imagery pool and the job state are shared, because they belong to the project rather than to a proposal.

What the pills guarantee

Switching a concept is not an undoable edit, and undo is per concept. A design edit stays with the concept it was made on. All of it survives a reload.

Where the design comes from

Nine numeric dials — density, imagery, expressiveness, motion, measure and the rest — plus a palette, two typefaces and a button family. A concept is those values; the page is what they resolve to.

Step 02 · Page flow

08 / 18

Which bands the page is made of, and why those.

A flow is an ordered list of section families — hero · text · split · cards · stats · testimonial · faq · cta and so on. The library holds 35 of them, and the model ranks every one against the brief, returning the five that fit with a reason for each.

The strategist can also describe the page in their own words; that goes to /outline and comes back as a custom sequence.

The flow decides families. Something else decides patterns.

Choosing a flow does not choose a design. Each family has many registered patterns, and which one a band gets is scored separately — see the next slide.

Every pattern is a real WordPress export — a tree of ds-blocks/* nodes with their attributes. Picking one is arithmetic and it is inspectable: the catalogue describes each pattern's look, what it is best for and what it holds; the brief and the nine design dials describe what this page needs. Matching the two produces a ranking with reasons.

Two properties matter as much as the ranking. It is deterministic — the same brief and dials give the same page every time, because a layout that reshuffles on each press is a slot machine, not a recommendation. And it varies with the concept, because the dials do: the calm concept gets contained bands, the bold one reaches for the photo-backed and full-bleed members of the same families.

Self-description is derived, not shipped

Each pattern's item counts, capability flags and one-line description are recomputed at boot from its own tree. They used to be stored, and they had drifted on two thirds of the library — which mattered, because pattern selection reads them.

The registry comes from the theme

npm run sync:registry reads the digitalsilk theme's own block.json manifests plus the attributes its editor HOCs inject. The export validates against that, so an imported block is editable with every control the builder used.

Step 03 · Modules

10 / 18

Per-band editing, in plain language.

Content

Pretitle, title, subtitle, body, the repeated items and the buttons. Typing patches the band in the live document as you type.

Media

Every slot the pattern actually renders, the found imagery, project assets and the placeholder library. Drag a tile onto the band to place it.

Layout + effects

Background, content width, spacing above and below, items per row, arrival effect, overlay and a decorative motif.

Every control lands in the export

A property you can change in the builder and cannot find in WordPress is worse than a missing control: the page was approved with it. So a test drives every binding the module editor renders — all 19 families, both views, a real input event each — and asserts the exported artifact changed.

It found five controls that changed nothing, each fixed at its cause. One was withdrawn rather than fixed: c-heading has a single alignment pair, so a separate supporting-text alignment had no attribute to become. It moved the preview and vanished on export.

Editing never moves the preview

A rebuilt srcdoc is a new document: it opens at scroll 0 and the restore walks it back down, taking the band you are editing with it. So a property change swaps one section in place and cancels the rebuild queued behind it. Repaints coalesce to one per frame, so dragging a slider patches the band per frame rather than rebuilding the page per pixel.

Two counters make it provable

paint.painted() and paint.rebuilt(). A repaint that silently degraded into a rebuild is the failure this exists to prevent, and a test asserting only "the change landed" cannot tell the two apart.

The preflight gates

One clear hero · a complete sequence · pattern provenance intact · every image has alt text · the palette passes contrast · and the rendered page passes contrast, which is a different question with a different answer.

The theme travels with the page

Not the slider numbers — the resolved token set: radii, container widths, vertical rhythm, the full type scale, motion duration and distance. WordPress consumes the exact values the preview used rather than reconstructing an approximation.

The AI layer · what the model is and is not asked

14 / 18

Seven prompts, each a versioned file in server/ai/prompts/ rather than a string in the code. Every response is validated by a Zod schema before it reaches the page: a reply that does not match is an error with a code, not a half-built page.

Never invent verifiable facts

No prices, client names, years in business, certifications, awards, review counts or staff names. Where a section structurally needs one, the model writes an instruction the strategist replaces.

One narrow exception, stated out loud

A stats band reading "add the measured figure" three times is a template, not a concept. So the model writes an illustrative figure in the unit the trade uses — 2,000 km, 48 hrs, 12 sites — and the band's own body says the figures are illustrative and to be confirmed.

Degradation is visible

No provider configured, a timeout, a refusal: each returns a typed error and the panel says which. A built-in planner covers the flow ranking so the page still builds, and the panel labels it as the built-in planner rather than the model.

Four runtime dependencies.

express, zod, dotenv, playwright. That is the whole list. The PDF reader, the ZIP reader, the deflate, the diagrams and the export are all platform APIs.

How the monolith is organised

builder.js is one IIFE with 21 numbered layers, each a dated commentary on what it changed and why. A layer reassigns the bindings it needs to change — renderPreview, updateBinding, syncSectionNode — so the history of every behaviour is readable in one file, in order.

What lives in shared/

19 ES modules used by the browser, the server and the tests: the design dials, the palette repair, the concept workspace, the brief schemas, the document readers, the style compiler. One statement of each rule.

Not the palette — the pixels, measured against each line's own ground, with a negative control that proves the instrument still fails.

Three things to know before extending it

The IIFE boundary is real

Code before builder.js:729 cannot see functions declared inside the layered section. Calling one from a listener throws a ReferenceError the browser swallows — the mutation applies, the repaint does not, and nothing is reported. Add to a layer, not above one.

The renderer is the contract

The preview and the export read the same node tree. Any change to one that is not a change to the other is the bug the whole verification stack exists to catch.

The theme is the authority

Not the pattern files, not the registry snapshot: the theme's block.json manifests plus the attributes its editor HOCs inject. Re-sync when the theme moves, and the export follows.
